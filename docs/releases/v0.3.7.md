# Amity Echo v0.3.7

Echo now starts a configured local development Cadenza service with a random credential stored in Windows Credential Manager. Developers no longer need to set `CADENZA_API_TOKEN`. A running service must accept Echo's existing credential; Echo does not replace unknown processes or rotate credentials after an authentication failure.

The `/model` picker, agent, and Amity task callback use one Echo inference boundary backed by the existing Cadenza/1 protocol. The picker still shows the models Cadenza actually reports, and the global selection persists across projects and sessions. Streaming, cancellation, usage, and reconnect behavior remain governed by Cadenza's native contract.

For local development, choose the installed Cadenza executable and its development JSON in `/settings` → **Local development inference**, or set `AMITY_CADENZA_HOME` to its installation directory. Echo does not install model packages or customer account infrastructure. The future customer topology will route authenticated inference through Amity when that service exists.
