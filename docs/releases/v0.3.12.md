# Amity Echo v0.3.12

- Resolve saved model selections against the live registry on startup and before new inference turns. A unique replacement with the same advertised logical ID updates the global selection and active conversation automatically.
- Keep the picker, global choice, reopened conversations and inference root consistent. Historical message roots remain unchanged, and in-flight requests stay pinned to their resolved artifact.
- Show the serving infrastructure's names, versions, descriptions, readiness and effective context. Fall back to the full advertised identity when no friendly name exists.
- Reject removed models, ambiguous replacements and identity changes on an existing root without silently selecting another model.

The current Cadenza/1 server does not designate an active/default deployment among multiple deployments of one logical model, or map renamed logical IDs. Such ambiguous selections still require an explicit picker choice. This release does not modify the server or install anything locally.

Validation: 24 isolated tests passed; real-service discovery, inference, cumulative streaming, cancellation and reconnect passed. Isolated terminal and headless sessions exercised stale-root recovery, current selection, global preference over historical session selection, preserved conversation messages and directory independence. The running service still advertised 128 context tokens; the separately corrected local Lyra deployment setting of 2,048 was not loaded by restarting the service during this work.
