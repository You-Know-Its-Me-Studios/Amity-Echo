Native Cadenza inference is now available in Echo.

- Replaces the previous inference providers with the authenticated proprietary Cadenza/1 WebSocket connection.
- Adds a native interactive `/model` picker with live discovery, model readiness, identity/root metadata, keyboard selection, and a global default shared across working directories.
- Preserves existing conversations and records model changes for future turns.
- Streams cumulative decoded text correctly, supports Ctrl+C cancellation and usage accounting, and reconnects for new requests after a service restart.
- Stores credential references in global configuration; supports environment credentials and Windows Credential Manager.
- Accepts ordinary Lyra foundation-model text without requiring JSON or treating text as permission to run tools.

## Install or update

Existing installations: run `echocli update`, then restart Echo.

For manual Windows x64 installation, download `echocli-x86_64-pc-windows-msvc.exe` and verify its matching `.sha256` file. The release also includes the pinned Amity host executable/checksum and `amity-echo-editor.vsix`.

Configure the Cadenza endpoint and credential reference under `/settings` → **Cadenza connection**, then select a model once through `/model`. The default endpoint is `ws://127.0.0.1:7941/cadenza`; the default credential reference is `env:CADENZA_API_TOKEN`. Cadenza must be running with the matching credential. Echo does not bundle model weights or start an inference service automatically.

## Verified

The native integration passed 16 isolated Rust tests, two separately invoked live integration checks, and real ConPTY testing of the installed Windows executable. Real Lyra generation, picker selection/cancellation, global persistence across restarts/directories, exact final text, token usage, Ctrl+C cancellation, invalid credentials, unavailable models, offline errors, and service-restart recovery were exercised. The release workflow also builds and runs the isolated Rust tests before publishing.

## Known limitations

- The pinned Amity host has separate fresh-workspace issues: overlapping candidate workspace paths and `ACL-CTX005: invalid task targets` during task creation. Full governed task creation/execution remains blocked in that baseline. No permission checks were weakened to bypass it.
- Current Lyra is a foundation model without advertised structured Echo tool-use support. Ordinary text responses work; completed instruction/tool training is required for structured agent workflows.
- Remote endpoints require certificate-verified `wss://`. Physical remote TLS deployment has not been accepted, and the current Cadenza service is loopback-only.
- Cadenza/1 has no image transport. Image references in existing conversations are preserved, but sending an image fails explicitly.

See the repository's `docs/cadenza.md` for protocol, migration, security boundaries, and acceptance details.
